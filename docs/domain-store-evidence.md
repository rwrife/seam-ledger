# Issue #2 domain/store review

`SeamLedgerKit` uses reduced nonnegative rational micrometres. Inputs are integer
numerators/positive denominators; factors cancel before checked multiplication.
Unknown allowances/counts are optional. Physical cut indices are one-based and
bounded by the known required count. A mirrored pair requires two pieces; fold
is an independent instruction. Unknown required counts must be reconciled before
cut events can be recorded.

Definitions are immutable. A `reconcile` event is an explicit reset of **all**
cut/sewn/pressed progress, retaining history and advancing the definition revision.
Callers must present this reset consequence before submitting reconciliation.
Old-revision actions are rejected. Sewn and pressed each have independent undo
events. Neither requires the other or a known allowance.

`ProjectStore` stores the initial definition plus ordered immutable events. Each
append batch replays, validates, and inserts inside one GRDB write transaction.
There is no separate definition update API. Separate store instances use separate
SQLite queues; tests use unique temporary directories and remove them afterwards.
GRDB is pinned to 7.8.0, revision
`18497b68fdbb3a09528d260a0a0e1e7e61c8c53d`. Package fetching is build-time only;
runtime networking remains prohibited by the gate.

## Fixture

`Packages/SeamLedgerStore/Tests/SeamLedgerStoreTests/Fixtures/v1.sqlite` is a real
SQLite database made with Python's standard-library sqlite3, not generated by the
test or the current migrator. Its schema is:

```sql
CREATE TABLE grdb_migrations (identifier TEXT NOT NULL PRIMARY KEY);
CREATE TABLE projects (id TEXT PRIMARY KEY NOT NULL, definition BLOB NOT NULL);
```

It has migration `v1-projects`, project `legacy`, and a UTF-8 JSON definition BLOB
containing a two-piece mirrored/fold piece `pair`, with no edges or seams. It has
no events table. Tests assert its pre-migration state, migrate to v2, preserve its
definition, append an event, and reopen. Fresh-store tests also prove transaction
rollback after a later invalid action and after a forced SQLite trigger failure.
